# VIGIL — SHARED DATA CONTRACTS

This document defines the standardized data contracts shared across all modules (`ml`, `fraud`, `graph`, `backend`, `frontend`). These contracts govern inter-module communication and JSON structures.

---

## 1. Transaction Contract

Representing an incoming financial transaction subject to screening and investigation.

### 1.1 JSON Example
```json
{
  "transaction_id": "TX8421",
  "timestamp": "2026-10-08T20:40:00",
  "account_id": "C102",
  "amount": 28900.0,
  "merchant_id": "M221",
  "device_id": "D901",
  "ip": "10.20.4.5",
  "location": "Chennai",
  "beneficiary_id": "B221"
}
```

### 1.2 Field Definitions

| Field Name | Type | Required / Optional | Description |
|---|---|---|---|
| `transaction_id` | `string` | **Required** | Unique identifier for the transaction (e.g., `"TX8421"`). |
| `timestamp` | `string` (ISO 8601) | **Required** | Date and time when the transaction occurred. |
| `account_id` | `string` | **Required** | Unique identifier of the initiating customer/account. |
| `amount` | `float` | **Required** | Monetary value of the transaction. |
| `merchant_id` | `string` | Optional | Recipient merchant ID (if payment transaction). |
| `device_id` | `string` | Optional | Unique fingerprint of the device executing the transaction. |
| `ip` | `string` | Optional | IP address of the initiating client. |
| `location` | `string` | Optional | Geographic location or city of the client. |
| `beneficiary_id` | `string` | Optional | Target account receiving funds (if peer-to-peer / transfer). |

## 2. ML Prediction Output Contract

Generated by `ml/` (CatBoost Classifier) for rapid initial screening.

```json
{
  "transaction_id": "TX8421",
  "fraud_probability": 0.91,
  "risk_level": "HIGH",
  "model_version": "catboost_v1.0"
}
```

* **`fraud_probability`**: `float` between `0.0` and `1.0`.
* **`risk_level`**: `string` enum (`"LOW"`, `"MEDIUM"`, `"HIGH"`).

```json
  "confidence": 0.88,

    "historical_avg_amount": 1200.0,
    "current_amount": 28900.0
  }
}
```

## 5. Evidence Item Contract

Generated by `backend/evidence/` combining indicators and counter-evidence.

```json
{
  "evidence_id": "EV_101",
  "signal_type": "SUSPICIOUS_DEVICE_SHARING",
  "category": "INDICATOR",
  "description": "Device D901 is shared across 5 distinct accounts within 12 hours.",
  "weight": 0.85,
  "source": "graph_analysis"
}
```

* **`category`**: Enum (`"INDICATOR"` for risk signals, `"COUNTER_EVIDENCE"` for why NOT to block).

```json

  "transaction_id": "TX8421",
  "risk_score": 89.5,
  "risk_level": "HIGH",
  "status": "PENDING_REVIEW",
  "decision": null,
  "analyst_notes": null,
  "created_at": "2026-10-08T20:41:00Z",
  "updated_at": "2026-10-08T20:41:00Z"
}
```

## 9. Human Decision Contract

Submitted by human fraud analysts through the frontend.

```json
{
  "case_id": "CASE_8421",
  "action": "BLOCK",
  "reason": "Confirmed ATO pattern and device sharing with blacklisted ring.",
  "analyst_id": "ANALYST_42",
  "timestamp": "2026-10-08T20:45:12Z"
}
```

* **`action`**: Enum (`"APPROVE"`, `"HOLD"`, `"ESCALATE"`, `"BLOCK"`).
